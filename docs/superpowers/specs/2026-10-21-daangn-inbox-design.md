# 당근 통합 채팅함 설계 (2026-10-21)

## 왜 만드나

당근 계정이 여러 개(지금 5개, 50개까지 늘 예정)라 폰마다 당근 앱을 열어 고객 문의를 확인하는 일이 힘들다.
기존에 쓰던 데스크톱 프로그램(INCOMPANY 채팅프로그램)은 계정 100개 버튼과 당근채팅 웹 창 4개 격자를 보여 주지만,
한 번에 4개 계정만 보이고 어느 계정에 안 읽은 문의가 쌓였는지 한눈에 알 수 없다.

원하는 것은 카카오톡처럼 **모든 계정의 채팅을 한 목록에 최근순으로** 보고, **안 읽은 것만 걸러** 보고,
**계정별로도 걸러** 보고, 그 자리에서 **자주 쓰는 답변 템플릿**으로 바로 답장하는 화면이다.

## 목표 · 비목표 · 반목표

목표
- 삼바 브라우저 안의 새 페이지 "당근"(사이드바 항목). 로그인한 모든 당근 계정의 채팅방을 한 목록으로 본다.
- 기본 보기는 **안 읽은 채팅만**, 최근 메시지 시각 내림차순. 전체 보기 토글.
- 왼쪽 계정 목록으로 계정별 필터. 계정마다 안 읽은 수 배지, 로그인 풀린 계정 표시.
- 채팅방을 고르면 오른쪽에 대화 내용과 답장 칸. 답장 칸 위에 자주 쓰는 답변 칩(누르면 입력칸에 채움, 편집 가능).
- 계정 추가는 QR 로그인(chat.daangn.com 로그인 화면을 그대로 보여 주고 폰으로 찍음). 한 번 로그인하면 세션이 유지된다.
- 새 메시지가 오면 PC 알림(계정 이름 + 상대 이름 + 내용 한 줄). 알림을 누르면 그 채팅방이 열린다.
- 계정 50개까지 PC 한 대에서 감당한다.

비목표(이번엔 안 한다)
- 사진·스티커 보내기, 거래 완료·예약 처리, 후기 보내기 — 당근 앱에서 한다.
- 비즈프로필 채팅(business-chat.daangn.com).
- 자동 답장(AI 답변). 템플릿은 사람이 고르고 사람이 보낸다.
- 다른 PC 와 계정 세션 동기화. 세션은 이 PC 의 파티션에만 있다.

반목표(이렇게 되면 실패)
- 한 계정 답장이 다른 계정으로 나가는 일. 계정·채팅방·세션이 한 줄로 묶여 있어야 한다.
- 안 읽은 문의가 목록에서 빠지는 일. 느리더라도 빠지면 안 된다.
- 폰에서 하던 로그인이 풀리는 일(당근 웹 로그인은 폰 앱과 동시 사용 가능하다 — 지금 INCOMPANY 프로그램도 그렇게 쓴다).

## 제약

- 당근채팅 웹(chat.daangn.com)은 공개 API 가 없다. 번들을 보면 채팅은 `wss://rocket-chat-pub.kr.karrotmarket.com/ws` 위에
  **protobuf** 로 오가고(Channel·Message·GetChannels… 수백 개 메시지 타입), 인증은 `karrotauth-http.kr.karrotmarket.com/v2/auth/refreshtokens` 의
  리프레시 토큰이다. 이 프로토콜을 직접 구현하는 것은 번들이 바뀔 때마다 깨질 위험이 크다.
- 따라서 **당근채팅 웹 페이지 자체를 계정마다 숨은 WebContentsView 로 띄워 두고, 그 DOM 을 읽고 입력칸에 글을 넣어 보내는 방식**으로 간다.
  삼바 브라우저는 이미 프로필별 `persist:` 파티션, 창 뒤에 붙여 두는 뷰(behind-views.ts), 페이지 스크립트 주입(page-bridge)을 갖고 있다.
- 계정 50개를 전부 상시 뷰로 띄우면 메모리가 수 GB 다. 상시 뷰 수에 상한을 두고 나머지는 돌아가며 확인한다(아래).
- 당근의 자동화 탐지 — 사람이 쓰는 PC 웹과 같은 UA·같은 페이지를 쓰고, 폴링은 DOM 읽기만이라 서버 요청을 늘리지 않는다.
- 코드 규칙은 저장소 CLAUDE.md 대로(한글 주석, 2칸 들여쓰기, 세미콜론 없음, any 금지, i18n ko/en).

## 화면(사용자가 고른 안 A)

세 단 구성. 시안: `.superpowers/brainstorm/328448-1792564530/content/inbox-layout.html`

1. 왼쪽 계정 패널(폭 190)
   - "전체" 줄(모든 계정 안 읽은 합계 배지) + 계정 줄들(별칭, 안 읽은 수 배지). 선택한 줄은 주황 왼쪽 띠.
   - 로그인 풀린 계정은 빨간 글씨 "로그인 풀림" — 누르면 QR 로그인 화면이 오른쪽에 뜬다.
   - 맨 아래 "＋ 계정 추가(QR 로그인)". 계정 줄 우클릭/⋯: 별칭 바꾸기, 지우기.
2. 가운데 통합 목록(폭 330)
   - 위 칩: [안읽음 N](기본) · [전체]. 정렬은 최근 메시지 시각 내림차순 고정.
   - 줄: 상대 이름 · 시각 / 마지막 메시지 한 줄 / 계정 별칭 · 상품명 · 안 읽은 수 배지. 답장한(안 읽음 0) 줄은 흐리게.
3. 오른쪽 대화(나머지)
   - 머리: 상대 이름·온도, 계정 별칭 칩, 상품명·가격.
   - 본문: 그 계정의 당근채팅 웹 채팅방 화면을 **그대로 끼워 넣는다**(그 계정의 숨은 뷰를 이 영역에 붙인다). 따라서 사진·스티커·거래 버튼이 당근 원래대로 보인다 — 다만 이번 목표는 글 답장뿐이다.
   - 아래: "자주 쓰는 답변" 칩 줄 + [＋ 편집]. 칩을 누르면 당근 입력칸에 글이 채워진다(보내기는 사람이 Enter/버튼).
   - 템플릿 편집: 작은 대화상자. 목록(끌어서 순서 바꾸기), 추가·수정·삭제. 계정과 무관하게 공통.

## 안쪽 구조

### 계정과 세션
- 테이블 `daangn_accounts(id, label, partition, display_name, profile_image, state, last_seen_at, created_at)`.
  `partition` 은 `persist:<작업공간접두사>__daangn-<id>__` — `__…__` 는 내부용 프로필 규칙이라 사용자 프로필 목록에 안 보인다.
  `state` 는 `logged_in | expired | loading`.
- 계정 추가: 새 파티션으로 숨은 뷰를 만들어 `https://chat.daangn.com/login` 을 열고 그 뷰를 오른쪽 영역에 붙여 QR 을 보여 준다.
  로그인이 끝나 채팅 목록 화면이 되면(DOM 에 계정 이름이 보이면) `display_name` 을 읽어 저장하고 별칭 기본값으로 쓴다.
- 로그인 풀림 판정: 뷰가 `/login` 또는 `accounts.daangn.com` 으로 가면 `expired`. 알림 한 번, 왼쪽 줄에 표시.

### 뷰 풀과 폴링(메인 프로세스, `src/main/daangn/`)
- 계정마다 `AccountView` 하나: 그 계정 파티션의 WebContentsView. 보이지 않을 때는 behind-views 방식으로 창 뒤에 붙여 둔다(뷰포트 0 이면 당근 웹이 목록을 안 그린다).
- **상시 뷰 상한** `daangnWarmViews`(설정, 기본 8). 계정이 상한 이하면 전부 상시. 넘으면 안 읽은 수가 있는 계정·최근 선택한 계정을 우선 상시로 두고, 나머지는 `daangnRotateIntervalSec`(기본 120초)마다 돌아가며 뷰를 잠깐 띄워 목록만 읽고 내린다.
- 각 뷰는 `daangnScanIntervalMs`(기본 5000)마다 채팅 목록 DOM 을 읽는다(`executeJavaScript`, 읽기만). 읽는 값: 방 id(URL `/room/<id>`), 상대 이름, 지역, 마지막 메시지·시각, 안 읽은 수, 상품 썸네일·제목.
  당근 웹은 "안읽은 메시지만 보기" 토글이 있으므로 켜 두면 안 읽은 방만 빠르게 읽힌다 — 전체 보기용으로는 토글을 끄고 한 번 더 읽는다.
- 모아서 `ChannelDto[]`(accountId 포함) 로 렌더러에 `daangn:updated` 로 보낸다. 메모리에만 둔다(재시작하면 다시 읽는다).
- 선택한 채팅방 열기: 그 계정 뷰에서 `/room/<id>` 로 이동시키고 뷰를 오른쪽 영역에 붙인다. 오른쪽 영역의 bounds 는 렌더러가 새 IPC(`daangn:room:bounds`)로 보내 준다 — 지금 네이티브 뷰 bounds 를 렌더러가 보내는 경로는 활성 탭용 `layout:set` 하나뿐이라 새로 만든다(폰 화면은 H.264 를 canvas 에 그리는 방식이라 참고 대상이 아니다). 다른 계정 방을 고르면 이전 뷰는 다시 뒤로 보낸다.
- 네이티브 뷰는 렌더러 DOM 위에 그려지므로 템플릿 편집 대화상자·토스트가 뜨는 동안에는 오른쪽 뷰를 접었다(뒤로 보냈다) 닫으면 다시 붙인다.
- 템플릿 넣기: 선택한 뷰의 입력칸(textarea)에 React 가 인식하도록 native setter + `input` 이벤트로 글을 넣는다. 보내기는 사람이 한다(잘못 보내기 방지).
- 읽음 처리는 당근 웹이 방을 열면 스스로 한다. 우리가 따로 하지 않는다.

### 알림
- 폴링에서 어떤 방의 안 읽은 수가 늘면 Electron `Notification` 한 번(제목 `[별칭] 상대 이름`, 본문 마지막 메시지). 같은 방은 2분 안에 다시 울리지 않는다.
- 알림 클릭 → 당근 페이지로 이동 + 그 방 선택.
- 설정: 알림 켜고 끄기(`daangnNotify`, 기본 켬).

### 템플릿
- 테이블 `daangn_templates(id, text, sort_order, created_at)`. 처음엔 비어 있고 사용자가 채운다(기본값 넣지 않는다 — 말투가 사람마다 다르다).
- IPC: `daangn:templates:list/save/delete/reorder`.

### IPC(`src/shared/daangn.ts` 에 DTO·상수)
- `daangn:accounts:list / add / remove / setLabel / relogin`
- `daangn:channels:list`(현재 모은 것), 이벤트 `daangn:updated`
- `daangn:room:open(accountId, roomId, bounds)` / `daangn:room:bounds(bounds)` / `daangn:room:close`
- `daangn:room:fillText(text)`(템플릿 채우기)
- `daangn:templates:*`
- 이벤트 `daangn:account-state`(로그인 풀림 등), `daangn:notify`(렌더러 토스트용)

### 선택자(깨짐 대비)
- chat.daangn.com DOM 선택자는 `src/main/daangn/selectors.ts` 한 파일에만 둔다. 읽기 실패가 3회 연속이면 그 계정 줄에 "화면 읽기 실패" 표시 + 로그. 다른 계정에 영향 없이 계속 돈다.
- 셀프 점검: 로그인된 계정이 있는데 목록을 하나도 못 읽으면 선택자 변경 가능성을 로그에 남긴다.

- 기본은 안 읽은 채팅만, 최근순. 계정별 필터. 자주 쓰는 답변 템플릿.

## 내가 정한 것(사용자가 안 정한 부분, 틀리면 고친다)
- 오른쪽 대화 영역은 당근 원래 채팅 화면을 끼워 넣는다(안 B 를 안 A 의 오른쪽에만 쓴 것). 사진·거래 기능이 공짜로 따라오고, 메시지 본문을 다시 그릴 필요가 없다.
- 보내기 버튼은 우리가 누르지 않는다. 템플릿은 입력칸까지만 채운다.
- 상시 뷰 기본 8개, 나머지 120초 순환. 설정에서 바꿀 수 있다.
- 템플릿은 계정 공통, 기본값 없음.
- 세션·목록은 이 PC 에만. 설정 동기화 대상에 넣지 않는다.

- 뷰 50개 시나리오의 메모리 측정과 상시 뷰 기본값 조정.

- QR 로그인 뷰가 로그인 완료를 알아채는 방법(URL 변화 + 계정 이름 DOM) 구현 세부.

## 빌더 점검에서 나온 것과 정한 것(모두 제 판단 — 틀리면 고친다)

1. **뷰는 TabManager 탭이 아니라 독립 WebContentsView 로 만든다.** TabManager 를 타면 파티션마다 확장(삼바웨이브·ADPICK 서비스워커)이 붙어 50벌이 뜨고, 탭 바·브릿지 탭 목록·AI 도구·사용자 탭 복원에 당근 뷰가 노출된다.
   독립 뷰는 페이지 preload·확장·금고 저장 바를 안 붙이고, 대신 직접 챙긴다: `setWindowOpenHandler`(채팅 안 링크는 기본 브라우저로 열고 새 창 금지), `will-navigate` 가드(chat.daangn.com·accounts.daangn.com 밖으로 못 나감), 권한 거부, 다운로드 거부, 대화상자 자동 닫기. 파티션이 `sessionHook` 을 타서 확장이 붙는지는 빌더가 확인하고, 붙으면 당근 파티션은 건너뛴다.
2. **뷰 풀은 앱 단위이고, 당근 페이지가 열린 창에 붙는다.** 뷰는 어느 BrowserWindow 에든 붙어야 뷰포트가 생기므로, 평소엔 기본(primary) 창의 behind-views 에 둔다. 당근 페이지가 다른 창에서 열리면 그 창으로 옮겨 붙이고(레인 탭의 exportTab/adoptTab 식), 같은 계정 뷰는 하나뿐이라 한 창에서만 열린다. 기본 창이 닫히면 풀 전체를 다음 창으로 옮긴다. 알림 클릭은 마지막으로 활성이던 창을 앞세운다.
3. **앱 시작부터 항상 돈다(계정이 1개 이상일 때만).** 알림을 지키려면 페이지를 안 열어도 돌아야 한다. 계정이 0개면 아무것도 안 띄운다. 설정 스위치 `daangnEnabled`(기본 켬)로 끌 수 있고, 하네스 결제 작업과 자원을 나눠 쓰므로 상시 뷰 기본 8개·폴링 5초가 결제 작업을 느리게 하면 숫자를 낮춘다.
4. **당근 계정은 작업공간과 무관하다.** 파티션 이름을 만들 때 작업공간 접두사를 박아 테이블에 저장하고, 그 저장된 문자열만 쓴다. 작업공간을 바꿔도 뷰 풀·알림은 그대로다.
5. **당근채팅 웹은 방을 열어도 왼쪽에 채팅 목록이 같이 보이는 2단이다**(보내 주신 화면으로 확인). 계정당 뷰는 1개로 충분하다 — 방을 연 동안에도 그 뷰의 목록 DOM 은 살아 있어 폴링이 계속된다. 오른쪽에 끼워 넣을 때는 CSS 주입으로 당근 자체 목록 패널만 `display:none` 으로 가린다(DOM 은 남아 읽을 수 있다). 영역 폭이 좁아져 당근이 1단(모바일) 배치로 바뀌면 최소 폭을 고정한다 — 빌더가 실제 화면에서 확인.
6. **순환 폴링 기준: 상시 뷰가 아닌 계정도 최소 3분 안에 한 번은 읽힌다.** 임시 뷰는 동시에 최대 3개까지, 한 계정당 목록이 그려질 때까지(최대 10초) 띄웠다 내린다. 42개 순환이면 한 바퀴 약 2분이다. 안 읽은 수가 있는 계정은 다음 순환에서 앞으로 당긴다.
